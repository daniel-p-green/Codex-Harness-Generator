# Self-Learning Rule

Use lightweight retrospectives for repeated issues, not for every small task.

- When a bug pattern repeats, write a short note under `Docs/_working/retro/`.
- Include the trigger, what fixed it, and what future work should check.
- Keep retro notes synthetic and free of private data.
- When five or more unprocessed retro notes exist, recommend consolidating them into project instructions.

This is advisory memory. It should improve future routing without becoming a source of unverified claims.
